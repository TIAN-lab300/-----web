# 测试与验收规范

日期：2026-09-30  
适用范围：个人本地待办应用 MVP

## 1. 测试目标

验证应用满足需求规格中的 FR-01 至 FR-12，并确认数据在刷新、异常存储和不同屏幕宽度下保持可用。

第一版不强制引入自动化测试框架。测试重点放在浏览器中的真实交互、存储行为和响应式布局。

## 2. 测试环境

至少使用一个现代桌面浏览器完成主流程测试。可使用浏览器开发者工具模拟手机宽度、键盘操作和本地存储异常。

测试前应清空当前测试站点的数据，或明确记录已有数据，避免旧任务干扰结果。

当前已生成两个自动化入口：

- `tests/app.test.cjs`：使用 Node 内置测试运行器验证纯任务逻辑、数据校验和存储适配。
- `tests/e2e.cjs`：使用 Playwright 驱动浏览器验证真实页面交互、刷新持久化、异常存储和响应式宽度。

纯逻辑测试运行方式：

```text
node tests\app.test.cjs
```

端到端测试需要可用的 Playwright 模块和浏览器可执行文件。测试通过环境变量 `BASE_URL` 和 `BROWSER_PATH` 指向本地静态服务和浏览器，不把这些依赖加入应用运行时。

## 3. 测试数据

建议使用以下数据：

- 普通任务：`完成第一版`
- 多个任务：`学习 HTML`、`学习 CSS`、`学习 JavaScript`
- 特殊字符：`<b>测试</b>`
- 长标题：连续输入长度超过 200 个字符的句子
- 空白输入：空字符串
- 只有空格的输入：多个半角或全角空格
- 未来截止时间：当前时间之后一小时
- 已过期截止时间：当前时间之前一小时

## 5. 数据层检查

### 5.1 空存储

删除存储键后加载页面：

- 不抛出阻断错误。
- 任务列表为空。
- 显示空状态。
- 添加任务后可以正常写入。

### 5.2 正确数据

写入符合版本 2 结构的数据后加载页面：

- 任务数量正确。
- 标题和完成状态正确。
- 截止时间正确恢复。
- 显示顺序正确。
- 剩余数量正确。

### 5.3 版本迁移

写入版本 1 数据后加载页面：

- 页面不崩溃。
- 原任务全部保留。
- 每个迁移任务的 `dueAt` 为 `null`。
- 不显示截止时间。
- 下一次成功保存后数据版本为 `2`。

### 5.4 损坏数据

分别测试：

- 无法解析的 JSON 字符串
- `null`
- 空数组作为顶层值
- 缺少 `tasks` 的对象
- 版本号既不是 `1` 也不是 `2`
- `tasks` 不是数组
- 任务缺少 `id`
- 任务标题为空
- `completed` 不是布尔值
- 时间字符串无法解析
- 版本 2 的 `dueAt` 不是 `null` 且无法解析
- 两个任务使用相同 `id`

每个场景都应回退为空任务列表，不崩溃，并显示存储提示。

### 5.5 保存失败

通过开发者工具或浏览器隐私设置模拟 `setItem` 失败：

- 页面不崩溃。
- 当前会话中的任务状态继续更新。
- 显示数据无法永久保存的提示。
- 不覆盖已有原始存储内容。

## 6. 交互检查

### 6.1 添加

- Enter 提交有效。
- 按钮提交有效。
- 输入首尾空格会被去除。
- 不设置截止时间可以正常创建。
- 设置截止时间后可以正常创建并显示。
- 提交后截止时间输入被清空。
- 连续快速提交不会创建重复任务。
- 提交后焦点回到输入框。

### 6.2 完成

- 点击复选框可以完成和取消完成。
- 完成任务在“全部”中仍显示。
- 完成任务在“未完成”中消失。
- 取消完成后任务重新出现在“未完成”中。
- 剩余数量同步更新。

### 6.3 编辑

- 点击编辑进入编辑状态。
- 保存有效标题后退出编辑状态。
- 修改截止时间后列表立即更新。
- 清除截止时间后不再显示期限区域。
- 取消后保留原标题。
- 空标题不能保存。
- 编辑状态在刷新后不会保留，任务内容仍保持最近一次成功保存的结果。

### 6.4 截止时间和逾期

- 未设置截止时间时不显示期限文本。
- 设置的截止时间显示到分钟。
- 未完成任务超过截止时间后显示“已逾期”。
- 未完成任务未超过截止时间时不显示逾期。
- 已完成任务即使超过截止时间也不显示逾期。
- 刷新页面后根据当前时间重新计算逾期状态。

### 6.5 删除

- 确认后删除任务。
- 取消后不删除任务。
- 删除当前筛选中的最后一个任务时显示空状态。
- 删除后剩余数量正确。

## 7. 响应式检查

至少检查以下宽度：

| 宽度 | 检查内容 |
| --- | --- |
| 320px | 无横向滚动，截止时间不溢出，按钮文字不被截断，长标题正常换行 |
| 375px | 任务标题、截止时间、表单和任务操作可点击，不遮挡内容 |
| 430px | 移动端布局稳定，日期时间输入和提示不遮挡输入区域 |
| 1024px | 主内容区宽度合理，截止时间和列表操作对齐 |

浏览器缩放也会改变有效布局宽度。测试时至少检查 100% 和 150% 缩放。

## 8. 无障碍检查

- 输入框有可识别的标签。
- 截止时间输入项有可识别的标签。
- 添加按钮有明确名称。
- 编辑和删除按钮有明确名称。
- 复选框可以使用空格键切换。
- 筛选按钮可以使用键盘切换。
- 当前筛选项不仅依赖颜色表达。
- 键盘焦点清晰可见。
- 剩余数量和存储提示可以被辅助技术读取。
- 页面标题层级合理。

## 9. 控制台检查

完成主要流程后检查浏览器控制台：

- 没有未捕获异常。
- 没有因空节点或无效 DOM 操作导致的功能错误。
- 没有网络请求失败，因为应用不应发出任务相关网络请求。
- 没有把任务标题输出到日志。
