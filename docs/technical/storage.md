# 本地存储规范

日期：2026-10-02  
适用范围：个人本地待办应用 MVP

## 1. 存储目标

应用必须把用户的全部任务主数据保存在当前浏览器中，并在刷新页面后恢复。提醒计划是任务数据的派生结果，为了支持页面关闭后的提醒，会同步到最小提醒后端。

任务存储使用浏览器 `localStorage`。提醒同步使用 HTTPS API。不引入 IndexedDB、Cookie 或 URL 参数作为任务主存储。

## 2. 存储键

固定存储键：

```text
personal-todo.mvp.v1
```

键名中的 `v1` 保留为兼容名称，不能随数据结构版本变化而直接改变。当前负载结构版本由 `version: 2` 表示。应用不创建多个任务集合，也不支持多用户。

提醒扩展还需要以下独立本地键：

```text
personal-todo.reminder-device.v1
personal-todo.reminder-sync.v1
```

- `reminder-device` 保存匿名设备标识、设备 secret 和订阅状态。
- `reminder-sync` 保存待同步版本、最近成功版本和失败信息。
- 这两个键不保存任务副本。

## 3. 存储结构

存储值是 JSON 字符串，反序列化后结构如下：

```json
{
  "version": 2,
  "tasks": [
    {
      "id": "task-id",
      "title": "完成第一版",
      "completed": false,
      "createdAt": "2026-09-30T10:00:00.000Z",
      "updatedAt": "2026-09-30T10:00:00.000Z",
      "dueAt": "2026-10-01T10:00:00.000Z"
    }
  ]
}
```

顶层字段：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `version` | number | 是 | 当前支持 `1` 和 `2`；读取版本 1 后迁移为版本 2 |
| `tasks` | array | 是 | 可以是空数组，不能为 `null` |

任务字段：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `id` | string | 是 | 非空、唯一 |
| `title` | string | 是 | trim 后非空 |
| `completed` | boolean | 是 | 只能是 `true` 或 `false` |
| `createdAt` | string | 是 | 有效时间字符串 |
| `updatedAt` | string | 是 | 有效时间字符串 |
| `dueAt` | string 或 null | 是 | `null` 表示未设置；非空时必须是有效时间字符串 |

版本 2 任务必须包含 `dueAt`。版本 1 任务没有该字段，迁移时补充为 `null`。

## 4. 创建任务

新建任务时：

1. 对输入标题执行 `trim()`。
2. 如果结果为空，拒绝创建。
3. 生成唯一 `id`。
4. 生成同一个 ISO 时间作为 `createdAt` 和 `updatedAt`。
5. 设置 `completed` 为 `false`。
6. 将可选截止时间转换为 ISO 时间；未设置时保存为 `null`。
7. 将任务加入 `tasks`。
8. 保存整个数据对象。

任务在界面中的显示顺序由 `createdAt` 倒序决定，不依赖数组当前顺序。

## 5. 更新任务

### 5.1 修改标题和截止时间

- 对输入值执行 `trim()`。
- 空值不能保存。
- 读取截止时间输入；空值保存为 `null`，非空值转换为 ISO 时间。
- 更新 `title`、`dueAt` 和 `updatedAt`。
- 保持 `id`、`createdAt` 和 `completed` 不变。

### 5.2 切换完成状态

- 反转 `completed`。
- 更新 `updatedAt`。
- 保持任务的其他字段不变。

### 5.3 删除任务

- 根据 `id` 从 `tasks` 中移除任务。
- 保持其他任务不变。
- 删除完成后立即写入存储。

## 6. 读取流程

读取按以下顺序执行：

1. 检查本地存储是否可用。
2. 读取固定键。
3. 如果没有值，返回：

```json
{
  "version": 2,
  "tasks": []
}
```

4. 对字符串执行 JSON 解析。
5. 校验顶层结构。
6. 如果版本为 `1`，为每个任务补充 `dueAt: null` 并将版本改为 `2`。
7. 校验每个任务。
8. 返回可信的版本 2 数据。

## 7. 校验规则

顶层数据必须满足：

- 值是非 `null` 对象。
- `version` 是数字且等于 `1` 或 `2`。
- `tasks` 是数组。

任务数据必须满足：

- 任务是非 `null` 对象。
- `id` 是非空字符串。
- `id` 在当前任务集合中不重复。
- `title` 是字符串。
- `title.trim()` 不是空字符串。
- `completed` 是布尔值。
- `createdAt` 和 `updatedAt` 可以转换为有效时间。
- 版本 2 任务的 `dueAt` 是 `null` 或可以转换为有效时间。

版本 1 迁移规则：

- 只接受顶层版本为 `1` 且任务字段合法的数据。
- 为每个任务增加 `dueAt: null`。
- 将顶层版本改为 `2`。
- 迁移结果可以正常写入原存储键。

第一版采用整体校验策略：

- 顶层结构或任一任务不合法时，整个存储结果回退为空任务列表。
- 不使用部分有效、部分忽略的混合结果。
- 回退时不崩溃，并显示数据读取提示。
- 第一次成功保存后再覆盖原始损坏数据。

## 8. 写入规则

每次任务集合发生变化后写入：

- 添加任务
- 修改标题或截止时间
- 切换完成状态
- 删除任务

写入内容必须包含完整 `version` 和 `tasks`。

写入顺序：

1. 将 `version` 和当前 `tasks` 序列化为 JSON。
2. 调用 `localStorage.setItem()`。
3. 如果成功，清除保存错误状态。
4. 如果失败，保留内存状态并显示非阻断提示。

不为每次按键、筛选切换或编辑模式切换写入存储。

如果变更影响开始时间、截止时间、重复规则或提醒，则本地任务写入成功后必须生成新的 `scheduleVersion`，并触发提醒计划同步。

## 9. 唯一标识

优先使用：

```text
crypto.randomUUID()
```

如果不支持，则使用时间戳和随机数的组合。生成后必须检查当前任务集合，确保没有重复标识。

标识只用于定位任务，不作为任务标题或用户可见信息。

## 10. 时间规则

统一使用 ISO 8601 字符串：

```text
2026-09-30T10:00:00.000Z
```

规则：

- 使用 `Date.prototype.toISOString()` 生成。
- 任务创建时 `createdAt` 和 `updatedAt` 相同。
- `dueAt` 由本地日期时间输入转换生成，未设置时为 `null`。
- 标题、截止时间或完成状态发生变化时更新 `updatedAt`。
- 仅切换编辑模式不算数据变化。
- 仅切换筛选项不算数据变化。
- 逾期状态不写入存储，而是由 `dueAt`、`completed` 和当前时间计算。

## 11. 错误处理

| 错误类型 | 检测方式 | 处理结果 |
| --- | --- | --- |
| 存储不可访问 | 属性访问或测试写入抛出异常 | 使用内存模式，显示提示 |
| JSON 解析失败 | 解析函数抛出异常 | 回退为空任务，显示提示 |
| 版本不匹配 | 版本号既不是 `1` 也不是 `2` | 回退为空任务，显示提示 |
| 版本 1 数据 | 检测到旧版本 | 补充 `dueAt: null` 并迁移为版本 2 |
| `dueAt` 非法 | 非空且时间无法解析 | 回退为空任务，显示提示 |
| 任务结构不合法 | 字段校验失败 | 回退为空任务，显示提示 |
| 保存配额不足 | `setItem` 抛出异常 | 保留内存任务，显示提示 |
| 浏览器隐私模式限制 | 访问或写入失败 | 使用内存模式，显示提示 |

错误提示不能使用阻断操作的模态框。当前页面应继续允许用户使用内存状态。

## 12. 版本升级

当前支持版本 `1` 和版本 `2`。

版本 1 到版本 2 的迁移是当前唯一迁移：

- 版本 1 任务没有截止时间。
- 迁移时为每个任务补充 `dueAt: null`。
- 保留任务标识、标题、完成状态和原有时间字段。
- 迁移后的下一次成功保存会写回版本 2。

未来增加版本时，不得静默改变已有数据的含义；无法转换的数据必须避免覆盖，并向用户说明。

## 13. 调试方法

在浏览器开发者工具控制台中：

读取当前数据：

```javascript
localStorage.getItem("personal-todo.mvp.v1")
```

删除当前数据：

```javascript
localStorage.removeItem("personal-todo.mvp.v1")
```

写入损坏数据以测试容错：

```javascript
localStorage.setItem("personal-todo.mvp.v1", "{broken json");
```

执行调试操作后刷新页面。删除存储键会清空应用任务，这是预期行为。

## 14. 隐私边界

- 任务主数据和备注默认保存在当前浏览器的本地存储中。
- 提醒后端只接收设备标识、订阅信息和提醒计划。
- 提醒计划可能包含任务标识、任务摘要、开始时间、截止时间和重复规则。
- 通知是否显示任务标题可以配置，默认优先使用最小隐私内容。
- 不将任务写入 Cookie 或 URL。
- 不使用第三方跟踪脚本读取任务。
- 用户清除站点数据后，任务不可恢复。
- 用户清除站点数据后，设备提醒订阅需要重新建立。

## 15. 提醒计划同步

提醒计划的来源始终是本地任务：

1. 本地任务保存成功。
2. 计算开始时间、截止时间、重复规则和提醒规则。
3. 生成提醒计划快照和 `scheduleVersion`。
4. 调用提醒 API 全量替换服务端计划。
5. 记录 `acceptedVersion`。

离线时：

- 本地提醒规则继续保留。
- 服务端可能继续运行旧计划。
- 网络恢复后立即同步最新版本。
- 旧版本请求不能覆盖新版本。

同步失败不能撤销本地任务保存。

## 16. 服务端存储边界

提醒后端数据库只允许保存：

- 设备标识
- 设备认证哈希
- PushSubscription
- 订阅状态和过期信息
- 提醒标识和任务标识
- 提醒时间、时区和重复规则
- 通知摘要
- 发送状态、重试次数和最后发送时间

提醒后端不得保存：

- 完整任务列表
- 子任务
- 备注全文
- 专注计时历史
- 任务完成历史

## 17. 删除和设备恢复

删除任务时：

- 删除本地任务。
- 生成新的提醒计划版本。
- 从后端删除该任务的提醒。

关闭提醒时：

- 停止后端调度。
- 可以保留本地提醒规则，方便再次启用。
- 用户选择彻底删除时才删除本地提醒规则。

清除浏览器数据时：

- 本地任务和设备认证信息丢失。
- 服务端旧订阅可能暂时残留，需要过期清理或用户重新注册后覆盖。
- 重新注册设备后重新创建订阅和提醒计划。

## 18. 提醒扩展的本地任务字段

提醒功能实现时，本地任务结构需要升级到版本 `4`，新增：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `startAt` | string 或 null | `null` | 计划开始时间 |
| `recurrence` | object | `{ "mode": "once", "weekdays": [], "timeZone": "..." }` | 重复规则 |
| `reminders` | array | `[]` | 相对开始时间或截止时间的提醒 |
| `seriesId` | string 或 null | `null` | 重复任务系列标识 |

提醒对象：

```json
{
  "id": "reminder-id",
  "anchor": "dueAt",
  "offsetMinutes": 30,
  "enabled": true,
  "lastTriggeredAt": null
}
```

这些字段在正式实现前只属于规划，不得提前写入当前版本 2 数据。
