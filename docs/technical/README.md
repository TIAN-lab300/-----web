## 2. 系统边界

本应用是一个纯前端、单用户、本地优先的静态 Web 应用。

系统包含：

- 浏览器页面
- 页面交互逻辑
- 浏览器本地存储

系统不包含：

- 后端服务
- 数据库服务
- 用户账号系统
- 网络 API
- 第三方分析或跟踪服务

因为不存在服务端接口，本阶段不提供 API 文档。

## 3. 运行时结构

第一版包含三个运行时文件：

```text
/
├── index.html
├── styles.css
└── app.js
```

文件职责：

| 文件 | 责任 |
| --- | --- |
| `index.html` | 提供语义化页面结构、任务标题与截止时间表单、筛选栏、任务列表和提示区域 |
| `styles.css` | 提供布局、响应式、截止时间、逾期、完成、空状态、错误状态和焦点样式 |
| `app.js` | 提供状态、数据校验、任务操作、本地存储、渲染和事件处理 |

不建立打包流程，不生成构建产物，不引入运行时依赖。

测试文件不参与浏览器运行：

```text
tests
├── app.test.cjs
└── e2e.cjs
```

## 4. 运行方式

应用可以通过静态服务器运行，也可以直接打开 `index.html`。

推荐在开发验证时使用静态服务器，以确保浏览器对当前站点来源和本地存储的行为一致。运行环境只需要支持现代浏览器和 `localStorage`。

验证步骤：

1. 打开应用。
2. 添加一个任务。
3. 为另一个任务设置截止时间。
4. 刷新页面并确认任务和截止时间仍然存在。
5. 完成、编辑、清除截止时间、删除和筛选任务。
6. 检查浏览器控制台没有阻断应用的错误。

如果通过本地服务器访问，关闭服务器不会删除浏览器已经保存的数据。

## 5. 架构与数据流

```text
用户操作
  -> DOM 事件
  -> 更新内存状态
  -> 写入 localStorage
  -> 重新渲染视图
```

读取流程：

```text
页面加载
  -> 读取 localStorage
  -> 解析和校验数据
  -> 建立 appState
  -> 渲染任务列表
```

视图状态和持久化状态必须分开：

- `tasks` 是需要持久化的数据。
- `filter`、`editingTaskId` 和存储提示属于当前页面状态。
- 筛选切换和编辑模式切换不写入本地存储。

## 6. 逻辑职责

### 6.1 存储适配

负责：

- 读取固定存储键
- 解析 JSON
- 校验版本和任务结构
- 将版本 1 数据迁移为版本 2
- 保存任务数据
- 捕获存储不可用和保存失败

存储适配不直接操作 DOM。

### 6.2 数据操作

负责：

- 创建任务对象
- 修改任务标题和截止时间
- 转换本地日期时间为 ISO 8601
- 切换完成状态
- 删除任务
- 计算当前筛选结果
- 计算未完成任务数量

数据操作优先写成接收输入并返回结果的函数，便于独立验证。

### 6.3 渲染

负责：

- 渲染任务列表
- 渲染完成状态
- 渲染截止时间和逾期状态
- 渲染编辑状态
- 渲染空状态
- 更新剩余数量
- 更新存储提示

用户输入必须通过 `textContent` 或文本节点写入页面，不允许使用 `innerHTML` 拼接任务标题。

### 6.4 事件处理

负责：

- 表单提交
- 筛选切换
- 完成复选框切换
- 编辑、保存和取消
- 删除确认
- 初始化

任务列表使用事件委托，不为每次重渲染重复绑定独立监听器。

## 7. 状态接口

运行时状态字段：

```text
appState
├── tasks: Task[]
├── filter: "all" | "active" | "completed"
├── editingTaskId: string | null
├── storageAvailable: boolean
└── storageNotice: string | null
```

约束：

- `tasks` 始终是任务数组，不能为 `null`。
- `filter` 只能取三个约定值之一，初始值为 `all`。
- `editingTaskId` 只能指向当前任务集合中的任务。
- `storageAvailable` 初始值由启动检查决定。
- `storageNotice` 为空表示没有需要显示的提示。

## 8. 实现约定

### 8.1 命名

- DOM 引用使用 `elements` 或明确的功能名称。
- 状态操作使用动词开头，例如 `addTask`、`updateTaskTitle`、`toggleTask`。
- 渲染函数使用 `render` 开头，例如 `renderTaskList`、`renderSummary`。
- 布尔值使用 `is`、`has` 或 `can` 前缀。

### 8.2 DOM 访问

- 页面初始化时集中获取必要的 DOM 引用。
- 渲染过程中不重复查询静态容器。
- 列表容器使用一个稳定挂载点。
- 动态任务节点使用 `data-task-id` 标识目标任务。

### 8.3 状态更新顺序

每次数据变化的顺序固定为：

1. 更新内存状态。
2. 尝试保存到本地存储。
3. 更新界面。

即使保存失败，当前页面仍应使用已经更新的内存状态工作。

### 8.4 输入处理

- 添加任务前对标题执行 `trim()`。
- 编辑任务保存前对标题执行 `trim()`。
- 截止时间为空时保存为 `null`。
- 非空截止时间必须转换为有效 ISO 8601 字符串。
- 空字符串不能进入任务集合。
- 特殊字符和 HTML 字符串只作为普通文字显示。

### 8.5 时间处理

- 创建时间使用 `new Date().toISOString()`。
- 用户通过 `datetime-local` 输入本地截止时间，再转换为 ISO 8601 保存。
- 状态、标题或截止时间发生变化时更新 `updatedAt`。
- 排序使用 `createdAt`，最新任务优先。
- 截止时间使用本地化格式显示到分钟。
- 未完成且 `dueAt` 早于当前时间时派生“已逾期”。
- 不按截止时间排序，不发送提醒。

## 9. 推荐实现顺序

1. 建立 `index.html` 的语义结构。
2. 建立 `styles.css` 的基础布局、响应式和状态样式。
3. 在 `app.js` 中实现存储读取、校验和保存。
4. 实现任务创建、标题与截止时间编辑、完成、删除、筛选和统计函数。
5. 实现列表、截止时间和逾期状态、空状态和提示的渲染。
6. 绑定表单、筛选栏和任务列表事件。
7. 执行 `docs/technical/testing.md` 中的测试用例。
8. 修复测试发现的问题并完成验收。

## 10. 性能与规模

第一版按个人使用场景设计，默认任务数量很小。

当前策略：

- 每次数据变化后完整重渲染任务列表。
- 不对任务列表使用虚拟滚动。
- 不建立缓存层。
- 不引入异步状态同步。

这些策略足以支持个人日常使用。只有实测出现明显性能问题时，才考虑优化渲染方式。

## 11. 安全与隐私

- 应用不发送任务数据。
- 应用不读取无关的浏览器数据。
- 任务标题只作为纯文本处理。
- 不在控制台输出任务内容。
- 不在 URL、Cookie 或页面查询参数中保存任务。
- 本地存储数据会随站点数据清除而消失。
